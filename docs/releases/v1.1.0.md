# v1.1.0 Release Plan

[English](v1.1.0.md) | [繁體中文](v1.1.0.zh-TW.md)

## Goal

Expand the current reduced O-A0003-001 model into a complete verified observation contract, then present the data through a clean bilingual GIS without overwhelming the map.

## Scope

v1.0.0 already requests O-A0003-001, but the parser currently keeps only a subset. v1.1.0 will preserve all fields observed in the verified current station schema that have application value.

### Station and location

- StationName / StationId
- ObsTime.DateTime
- WGS84 latitude / longitude
- CoordinateName / CoordinateFormat
- StationAltitude
- CountyName / TownName
- CountyCode / TownCode

### Current weather elements

- Weather
- VisibilityDescription
- SunshineDuration
- Now.Precipitation
- WindDirection / WindSpeed
- AirTemperature
- RelativeHumidity
- AirPressure
- UVIndex

### Wind extremes

- Max10MinAverage.WindSpeed
- Max10MinAverage.Occurred_at.WindDirection
- Max10MinAverage.Occurred_at.DateTime
- GustInfo.PeakGustSpeed
- GustInfo.Occurred_at.WindDirection
- GustInfo.Occurred_at.DateTime

### Daily temperature extremes

- DailyHigh temperature and occurrence time
- DailyLow temperature and occurrence time

## Data Contract Rules

- Verify a fresh real API response before coding.
- Preserve raw CWA meaning and units.
- Use WGS84 for Leaflet.
- Normalize documented missing / abnormal sentinel values at the application boundary.
- Do not show technical sentinels such as `-99`, `-98`, `990`, or `X` directly to users.
- Keep raw weather values separate from localized presentation strings.
- Update sanitized fixtures and parser tests before changing SQLite.

## GIS Information Architecture

Data completeness does not mean every field becomes a map layer.

### Primary map layers

1. Temperature
2. Humidity
3. Precipitation
4. Wind
5. Pressure
6. UV Index
7. Weather

Only one primary observation layer should be active at a time.

### Station Detail Panel

Selecting a station opens a structured details panel.

**Current Conditions**
- Weather
- Temperature
- Humidity
- Precipitation
- Pressure
- UV Index
- Visibility
- Sunshine duration

**Wind**
- Current direction / speed
- Maximum 10-minute average wind and occurrence
- Peak gust speed / direction / occurrence

**Today**
- Daily high temperature + occurrence time
- Daily low temperature + occurrence time

**Station**
- Station name / ID
- County / township
- Administrative codes
- Altitude
- Coordinates
- Observation time

## Visual Direction

```text
Full-screen map
+ compact top status bar
+ right-side layer panel
+ contextual legend
+ station detail drawer/card
```

- Keep the map dominant.
- Use color primarily for the active metric.
- Use consistent metric cards and typography.
- Avoid displaying every field directly on markers.
- Use progressive disclosure: overview first, station details on selection.
- On mobile, convert details to a bottom sheet or compact overlay.
- Keep map attribution visible.

| Metric | Suggested map treatment |
| --- | --- |
| Temperature | sequential color + numeric marker |
| Humidity | blue/cyan scale + percentage |
| Precipitation | blue scale; emphasize values above zero |
| Wind | speed color + compact direction arrow |
| Pressure | restrained sequential scale |
| UV Index | low → extreme categories |
| Weather | compact condition symbol |

## Bilingual UI

Supported locales:

```text
en
zh-TW
```

Use a small typed TypeScript dictionary instead of adding a large i18n framework.

Suggested structure:

```text
web/src/i18n/
├── locale.ts
├── en.ts
└── zh-TW.ts
```

Localization covers the page title, layer names, legends, station details, loading / empty / error states, date/time formatting, and the language selector. Locale preference may be stored in localStorage.

Numeric observations remain unchanged; localization belongs to the presentation layer.

## Gate Re-entry

v1.1.0 changes the parser, persistence model, JSON contract, frontend types, and GIS UI. The earliest affected Gate is therefore Gate 1.

```text
Gate 1 → Gate 2 → Gate 3 → Gate 4 → Gate 5
```

### Gate 1
- Inspect a fresh real O-A0003-001 response.
- Update sanitized fixture.
- Expand parser output and tests.

### Gate 2
- Expand SQLite schema and UPSERT.
- Verify new columns using real integration data.
- Expand JSON export and tests.
- Preserve idempotent reruns.

### Gate 3
- Expand WeatherObservation.
- Add metric formatting / classification tests.
- Add new map layers and station detail UI.
- Add English / Traditional Chinese locale support.
- Perform manual verification in both languages.

### Gate 4
- Run full Pester, frontend tests, and production build.
- Verify clean checkout and documentation parity.

### Gate 5
- Deploy the new build.
- Verify both languages, all layers, station details, missing values, and scheduled data refresh.

## Definition of Done

- Verified O-A0003 fields survive Parser → SQLite → JSON.
- Frontend types match the expanded contract.
- Temperature, humidity, precipitation, wind, pressure, UV, and weather layers work.
- Remaining fields are organized in Station Detail.
- English and Traditional Chinese UI are complete.
- Raw technical sentinel values are not exposed to users.
- Gate 1–5 verification is green for the v1.1.0 release commit.
